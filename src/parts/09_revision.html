13Quick Revision Sheet

Read this the night before the exam. Every line is explained in detail in the sections above.

Transactions & ACID
  • Transaction = logical unit of work; read(X) → buffer, write(X) → back to DB.
  • Commit = make permanent; Rollback = undo everything.
  • A: all-or-nothing (recovery/undo). C: valid → valid (programmer + constraints). I: as if serial (concurrency control). D: committed survives crashes (recovery/redo).
  • States: Active → Partially committed → Committed; Active/PC → Failed → Aborted → restart / kill.
Concurrency problems
  • Lost update: W–W, second write overwrites first.
  • Dirty read: W–R on uncommitted data; fix = read committed / strict 2PL.
  • Unrepeatable read: R–W, same item two values.
  • Phantom: insert/delete changes the set of rows matching a condition.
  • Serial: consistent but slow. Concurrent: fast, needs control. Parallel: truly simultaneous on many CPUs.
Serializability
  • Conflict = different txns + same item + at least one write.
  • Precedence graph: Ti → Tj if Ti’s op conflicts with and precedes Tj’s op. Cycle ⇒ not CS; acyclic ⇒ CS, serial order = topological sort.
  • View equivalence: same initial reads, same reads-from, same final writes.
  • CS ⇒ VS; VS but not CS ⇒ blind writes. VS test NP-complete ⇒ test CS first.
  • n transactions ⇒ n! serial schedules.
Recoverability
  • Recoverable: if Tj reads from Ti, Ti commits before Tj commits.
  • Cascading rollback: one abort forces many.
  • Cascadeless: read only committed data (Ti commits before Tj reads).
  • Strict: no read or write of X until last writer of X commits/aborts.
  • Serial ⊂ Strict ⊂ Cascadeless ⊂ Recoverable.
Locking
  • S (read, shareable) / X (read+write, exclusive). Only S–S compatible.
  • 2PL: growing (only acquire) then shrinking (only release); lock point = last lock. Guarantees CS; not deadlock-free; can cascade.
  • Strict 2PL: X held till commit ⇒ cascadeless, recoverable. Rigorous: all locks till commit ⇒ serial order = commit order.
  • Conservative: all locks before start ⇒ deadlock-free, needs advance knowledge.
  • Rigorous ⊂ Strict ⊂ Basic; conservative separate.
Deadlock
  • Cycle of waiting transactions; starvation = one waits forever while others proceed.
  • Prevention: conservative 2PL, item ordering, wait-die (older waits, younger dies), wound-wait (older wounds, younger waits), timeout.
  • Detection: cycle in wait-for graph ⇒ choose min-cost victim, roll back, avoid starvation.
Recovery
  • Failures: transaction, system crash (memory lost), disk failure. Storage: volatile / non-volatile / stable.
  • Log: <Ti start>, <Ti, X, old, new>, <Ti commit>, <Ti abort>, <checkpoint L>. WAL: log before data.
  • Deferred: write after commit; redo committed only (NO-UNDO/REDO).
  • Immediate: write anytime; undo uncommitted, redo committed (UNDO/REDO).
  • Checkpoint: flush log + dirty pages + <checkpoint L>; recover only from last checkpoint. Frequent ⇒ faster crash recovery, slower normal work; no effect on media recovery.
  • Shadow paging: current vs shadow page table; commit = switch pointer; NO-UNDO/NO-REDO; fragmentation, GC, commit overhead.
Security
  • CIA: confidentiality, integrity, availability. Security (unauthorised) vs integrity (correctness).
  • Controls: access, inference, flow, encryption; DBA: create accounts, grant, revoke, assign levels.
  • DAC: GRANT … [WITH GRANT OPTION]; REVOKE … CASCADE | RESTRICT; grant graph; views; roles.
  • MAC: TS > S > C > U; Bell–LaPadula: no read up, no write down. RBAC: privileges to roles.
  • SQL injection → prepared statements. Encryption at rest/in transit; hashing passwords; audit trail.
Answer-writing checklist for numericals
  1. Number every operation of the schedule.
  2. Precedence graph: go item by item; list conflicting pairs with step numbers; draw graph; state cycle / topological order.
  3. Recoverability: make a reads-from table, then check commit order (recoverable), commit-before-read (cascadeless), commit-before-read-or-write (strict).
  4. 2PL questions: draw the growing/shrinking graph; check each transaction separately; for deadlock show the hold-and-request interleaving.
  5. Log questions: write the log in the right format; for each crash point list committed (redo) and uncommitted (undo/ignore) transactions and give final values.

13.2 Two-mark questions (one-line answers)

QuestionAnswer
What is a transaction?A logical unit of work consisting of one or more database operations that must execute completely or not at all.
What are ACID properties?Atomicity, Consistency, Isolation, Durability — properties every transaction must satisfy for reliable processing.
What is a schedule?The order in which operations of concurrent transactions are executed, preserving the order within each transaction.
What is a serializable schedule?A (non-serial) schedule equivalent to some serial schedule of the same transactions.
When do two operations conflict?Different transactions, same data item, and at least one is a write.
What is a blind write?A write of an item by a transaction that has not read that item before.
What is a lost update?One transaction’s update is overwritten by another that read the same old value.
What is a dirty read?Reading a value written by a transaction that has not yet committed.
What is a phantom read?Re-running a query returns new or missing rows because another transaction inserted/deleted matching rows.
What is a recoverable schedule?If Tj reads from Ti, then Ti commits before Tj commits.
What is a cascadeless schedule?Transactions read only committed data (writer commits before the read).
What is a lock?A variable associated with a data item that controls concurrent access to it (S = shared/read, X = exclusive/write).
What is 2PL?A locking protocol with a growing phase (only acquire) followed by a shrinking phase (only release); it guarantees conflict serializability.
What is a lock point?The moment a transaction acquires its last lock (end of the growing phase).
Why is conservative 2PL called static 2PL?Because the transaction declares and acquires its whole lock set before it starts.
What is a deadlock?A set of transactions each waiting for a lock held by another in the set, so none can proceed.
What is starvation?A transaction waits indefinitely (or is repeatedly rolled back) while others progress.
What is a wait-for graph?A graph with edge Ti → Tj if Ti waits for a lock held by Tj; a cycle means deadlock.
What is a log?A sequential file on stable storage recording start, update (old/new values), commit and abort of transactions.
What is Write-Ahead Logging?A log record must reach stable storage before the corresponding data block is written to disk.
What is a checkpoint?A point where log and dirty buffers are flushed and <checkpoint L> is written, so recovery can start from there.
What is the commit point?The moment the <Ti commit> record is on stable storage; after it the transaction is committed and must be redone after a crash.
What is shadow paging?Recovery using a shadow page table (unchanged) and a current page table; commit atomically switches to the current table.
Undo vs redo?Undo restores old values of uncommitted transactions; redo re-applies new values of committed ones.
What is the CIA triad?Confidentiality, Integrity, Availability — the three goals of database security.
Authentication vs authorization?Authentication verifies who the user is; authorization decides what that user may do.
What is SQL injection?An attack where malicious input changes the meaning of an SQL query; prevented by parameterized queries.
