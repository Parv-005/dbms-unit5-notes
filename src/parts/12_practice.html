Practice 2Conflict serializability

Is R1(A), R2(B), W1(A), R3(A), W2(B), W3(A) conflict serializable? List every equivalent serial order.

T2 works only on B, so it is independent; T1 must precede T3.

Practice 3Conflict serializability

Is R1(A), W1(A), R2(A), W2(A), R2(B), W2(B), R1(B), W1(B) conflict serializable?

Show answer
{{edges:pr3}}{{pgraph:pr3}}{{verdict:pr3}}

On A, T1 goes first; on B, T2 goes first — no serial order can satisfy both.

Practice 4Recoverability

r1(X); w1(X); r2(X); w2(X); c2; c1 — recoverable? cascadeless? strict?

Show answer
{{sched:pr4}}{{recov:pr4}}

T2 reads X from uncommitted T1 and then commits before T1. If T1 now aborted, the committed T2 could not be undone ⇒ not recoverable (and therefore not cascadeless or strict). Fix: move c2 after c1.

Practice 5Recoverability

r1(X); w1(X); r2(Y); c1; r2(X); w2(X); c2 — recoverable? cascadeless? strict?

Show answer
{{sched:pr5}}{{recov:pr5}}

T2 touches X only after T1 has committed ⇒ recoverable, cascadeless and strict.

Practice 6Serializability + recoverability

r1(A); r2(A); w1(A); w2(A); c1; c2 — which concurrency problem is this? Is it conflict serializable? Recoverable? Strict?

Show answer
{{sched:pr6}}{{pgraph:pr6}}{{verdict:pr6}}{{recov:pr6}}

Both read the same A and both write it: T1’s write is overwritten by T2 — a lost update. Not conflict serializable. No transaction reads another’s write, so it is recoverable and cascadeless, but T2’s write of A over T1’s uncommitted write makes it not strict. This shows that serializability and recoverability are separate questions: a schedule can be recoverable and still be wrong.

Practice 72PL

Does this transaction follow 2PL?  lock-S(A); read(A); unlock(A); lock-X(B); read(B); write(B); unlock(B)
If not, rewrite it so that it follows (a) basic 2PL and (b) rigorous 2PL.

Show answer

No. It acquires lock-X(B) after it has already released A — a lock acquired in the shrinking phase.

(a) Basic 2PL: lock-S(A); read(A); lock-X(B); unlock(A); read(B); write(B); unlock(B) (lock point = lock-X(B)).

(b) Rigorous 2PL: lock-S(A); read(A); lock-X(B); read(B); write(B); commit; unlock(A); unlock(B).

Practice 8Log-based recovery

Immediate modification. Log: <T1 start>, <T1, A, 100, 200>, <T2 start>, <T1 commit>, <T2, B, 50, 80>, <T3 start>, <T3, A, 200, 250> — crash. What does recovery do, and what are the final values of A and B?

Show answer
  • T1 has start and commit ⇒ redo: A = 200.
  • T2 and T3 have no commit ⇒ undo, scanning backwards: T3’s record → A ← 200; T2’s record → B ← 50.

Final: A = 200, B = 50. Write <T2 abort> and <T3 abort>.

With deferred modification the result is the same: redo T1, ignore T2 and T3.

15.2 MCQ self-test

Q1. Which ACID property ensures that a committed transaction survives a system crash?

  1. Atomicity
  2. Consistency
  3. Isolation
  4. Durability
Answer

D. Durability — ensured by the recovery manager through the log and redo.

Q2. Which pair of operations on the same item, by different transactions, does NOT conflict?

  1. Read–Write
  2. Write–Read
  3. Read–Read
  4. Write–Write
Answer

C. Read–Read — Two reads never conflict — the order doesn’t change what either sees.

Q3. A transaction reads data written by another transaction that has not committed. This is:

  1. Lost update
  2. Dirty read
  3. Phantom read
  4. Deadlock
Answer

B. Dirty read — a W–R conflict on uncommitted data.

Q4. The same query returns an extra row on its second execution. This is:

  1. Lost update
  2. Dirty read
  3. Non-repeatable read
  4. Phantom read
Answer

D. Phantom read — the set of rows satisfying the condition changed.

Q5. A precedence graph with a cycle means the schedule is:

  1. Conflict serializable
  2. Not conflict serializable
  3. Serial
  4. Strict
Answer

B. Not conflict serializable — Cycle ⇒ not conflict serializable.

Q6. With n transactions, the number of possible serial schedules is:

  1. n
  2. 2ⁿ
  3. n!
  4. n²
Answer

C. n! — every ordering of the n transactions is a different serial schedule.

Q7. Every conflict-serializable schedule is:

  1. Not view serializable
  2. View serializable
  3. Always serial
  4. Not recoverable
Answer

B. View serializable — CS ⇒ VS (not the other way round).

Q8. A schedule that is view serializable but not conflict serializable must contain:

  1. Dirty reads
  2. Blind writes
  3. Deadlocks
  4. Phantoms
Answer

B. Blind writes — e.g. w1(A), w2(A), w1(A).

Q9. Which is a classic view-serializable but not conflict-serializable schedule?

  1. r1(A), r2(A)
  2. w1(A), w2(A), w1(A)
  3. r1(A), w1(A), r2(B)
  4. r1(A), r2(B)
Answer

B. w1(A), w2(A), w1(A) — Final write by T1 in both it and serial ⟨T2, T1⟩; precedence graph has T1 ⇄ T2.

Q10. In a cascadeless schedule:

  1. Transactions read only committed data
  2. Every transaction is serial
  3. Deadlocks cannot occur
  4. No transaction writes data
Answer

A. Transactions read only committed data — The writer commits before anyone reads its value.

Q11. Which phase of 2PL allows a transaction to acquire new locks?

  1. Shrinking
  2. Growing
  3. Commit
  4. Recovery
Answer

B. Growing — locks can only be acquired (or upgraded), never released.

Q12. Strict 2PL holds which locks until commit or abort?

  1. Only shared
  2. Only exclusive
  3. Both shared and exclusive
  4. None
Answer

B. Only exclusive — Only X-locks; S-locks may be released earlier.

Q13. Rigorous 2PL holds:

  1. Only shared locks till commit
  2. Only exclusive locks till commit
  3. Both shared and exclusive locks till commit
  4. No locks
Answer

C. Both shared and exclusive locks till commit — All locks till the end ⇒ serial order = commit order.

Q14. Conservative 2PL is also known as:

  1. Dynamic 2PL
  2. Static 2PL
  3. Strict 2PL
  4. Rigorous 2PL
Answer

B. Static 2PL — Static, because the lock set is declared before execution.

Q15. In conservative 2PL, if even one required lock is unavailable, the transaction:

  1. Acquires the remaining locks
  2. Starts executing
  3. Waits without acquiring any lock
  4. Aborts permanently
Answer

C. Waits without acquiring any lock — No partial acquisition ⇒ no hold-and-wait ⇒ no deadlock.

Q16. Which 2PL variant is deadlock-free?

  1. Basic
  2. Strict
  3. Rigorous
  4. Conservative
Answer

D. Conservative — all locks are taken up front, so there is no hold-and-wait and no circular wait.

Q17. In wait-die, a younger transaction requesting a lock held by an older one:

  1. Waits
  2. Dies (is rolled back)
  3. Wounds the older one
  4. Gets the lock immediately
Answer

B. Dies (is rolled back) — Younger dies; older waits.

Q18. Which operation restores the old value of a data item?

  1. Redo
  2. Undo
  3. Commit
  4. Checkpoint
Answer

B. Undo — Undo writes the before-image.

Q19. With deferred database modification, recovery needs:

  1. Only undo
  2. Only redo
  3. Both undo and redo
  4. Neither
Answer

B. Only redo — Uncommitted changes never reached the database ⇒ NO-UNDO/REDO.

Q20. Write-Ahead Logging requires that:

  1. Data blocks are written before log records
  2. Log records are written before the corresponding data blocks
  3. The log is kept in main memory
  4. Checkpoints are taken after every write
Answer

B. Log records are written before the corresponding data blocks — Log first, data later.

Q21. Increasing checkpoint frequency mainly:

  1. Speeds up recovery from a system crash
  2. Speeds up recovery from a disk failure
  3. Improves normal performance
  4. Removes the need for a log
Answer

A. Speeds up recovery from a system crash — Less log to process after a crash; media recovery depends on dumps.

Q22. Shadow paging is a recovery technique of type:

  1. UNDO/REDO
  2. NO-UNDO/REDO
  3. UNDO/NO-REDO
  4. NO-UNDO/NO-REDO
Answer

D. NO-UNDO/NO-REDO — Crash before commit ⇒ keep the shadow table; nothing to undo or redo.

Q23. Which security goal ensures data is accessible to authorised users when needed?

  1. Confidentiality
  2. Integrity
  3. Availability
  4. Authentication
Answer

C. Availability — e.g. protection against denial-of-service and ransomware.

Q24. Bell–LaPadula’s ★-property says:

  1. No read up
  2. No write down
  3. No read down
  4. No write up
Answer

B. No write down — No write down (simple security property = no read up).

Q25. Which SQL clause allows a user to pass a received privilege to others?

  1. CASCADE
  2. WITH GRANT OPTION
  3. RESTRICT
  4. PUBLIC
Answer

B. WITH GRANT OPTION — without it, the receiver can use the privilege but not grant it.
